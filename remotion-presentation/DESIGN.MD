# Remotion 演示过程录制

演讲者打开已有的 Remotion 作品，点 **开始录制**，边操作边讲解。浏览器把选中的画面和麦克风声音一起录成视频。按键触发的运镜、动画、回退和每次讲解停顿，都按实际发生的顺序和时长进入成片。

例如，镜头从工作流全景推入一个节点。你停下来讲了 12 秒，又倒回去重播一次。成片里会依次出现推近、12 秒的讲解和重播。录制的依据是浏览器画面与麦克风，不需要根据按键日志重建时间轴。

## 怎么开始和结束

| 你正在用什么 | 打开方式 | 共享什么画面 |
| --- | --- | --- |
| 任意已有的 Remotion 项目 | 在录制电脑单独打开录制页，点「开始录制」 | 在浏览器弹窗中选已经打开的 Studio、预览标签页或窗口 |
| 仓库里的 `workflow-vs-agent` 演示 | 运行 `npm run presentation`，点演示工具栏的「开始录制」 | 在弹窗中选当前演示标签页 |

随文提供的单文件「演示录制.html」包含完整录制控件。下载后用桌面浏览器打开即可使用。如果本地文件的共享权限受限，在仓库根目录运行下面的命令，然后访问 `http://127.0.0.1:4177/`。这条路径只使用 Node 自带模块，目标项目可以运行在不同的地址，也无需修改源码。

```bash
node remotion-presentation/recorder/serve.mjs
```

麦克风默认勾选。选好画面、允许麦克风后，按钮变成「停止录制」并开始计时，这时可以讲了。可以在录制页点「停止录制」，也可以直接点浏览器的「停止共享」。独立录制页支持回看结果，两种入口都会提供 **下载视频**。

在集成的演示里，`F` 全屏并隐藏工具栏，`Shift+R` 停止录制并显示下载入口。普通的 `R` 重播动画，`P` 暂停动画；讲到哪一帧停下、讲多久，都不会中断录制。选标签页时，切回独立录制页操作也能保持目标画面。选整块屏幕时，切换窗口的过程也会被录进去。

## 和目标工程的边界

```text
已有 Remotion 项目 → 浏览器显示的画面 ─┐
                                      ├→ MediaRecorder → 本地视频文件
演讲者的麦克风 ───────────────────────┘
```

- **作品负责演示。** Remotion 继续绘制原有特效，演讲者照常使用作品自己的按键和控件。独立录制页不读取作品的场景、分镜、字幕、帧率或停留点。
- **录制器负责采集。** 用户点击开始后，`getDisplayMedia` 请求共享画面，`getUserMedia` 请求麦克风。两路轨道合到同一个 `MediaStream`，由 `MediaRecorder` 编码。第一版的声音来自麦克风。需要无声视频时可取消勾选。
- **工具栏复用同一个按钮。** 独立页和演示工具栏挂载同一个原生网页组件 `<remotion-recorder>`。共享演示组件只在录制开始时恢复键盘焦点、结束时显示下载入口。录制器自身不依赖 React 或 Remotion。

## 文件和录制结果

| 仓库路径 | 用途 |
| --- | --- |
| `remotion-presentation/recorder/recorder.js` | 权限申请、录制按钮、计时、停止、回放与下载 |
| `remotion-presentation/recorder/index.html` | 可独立打开的录制界面 |
| `remotion-presentation/recorder/serve.mjs` | 通过本机 localhost 提供上述两个静态文件 |
| `remotion-presentation/src/Presentation.tsx` | 现有演示工具栏中的录制入口 |

浏览器在本机编码，工具根据实际容器生成文件后缀，常见结果为 WebM 或 MP4。录制期间的数据暂存在当前页面，长录制会占用更多浏览器存储资源。请先点击下载，再关页或刷新。浏览器会提示授权，录制服务不接收视频或声音。

请求被取消或麦克风授权失败时，工具释放已取得的轨道，允许重新开始。录制中如果浏览器停止共享或麦克风断开，工具收尾并提供已收到的数据。只有收到编码器的最后一块视频数据后才生成下载链接。
