# Agent 是什么？从两份官方定义说起

8 镜 / 预计 1:54 / 1920 × 1080 / 30 fps / 3420 帧。

**内容定位：** 两分钟以内的概念短片。以 Anthropic《Building effective agents》和 OpenAI《A practical guide to building agents》的说法为主，提取 Agent 的定义、基本构成和执行特征，再给出一句容易记住的归纳。

**一句话主题：** Agent 的关键，不是“用了大模型”，而是模型参与了执行过程中的决策。

**稿件依据：** [Agent是什么\_.md](./Agent是什么_.md)、已有三张附件，以及文末核对过的官方原文。按仓库 `pldz-tech-video` 技能编写。

**主线：** Anthropic 怎么区分架构 → OpenAI 怎么定义 Agent → 两家共同强调什么 → 用一张简图说明执行与反馈 → 回到完整定义。贯穿全片的问题只有一个：**下一步，是谁决定的？**

### S02 · Anthropic：让模型动态决定执行过程

0:08–0:28 / 20 秒 / 帧 `[240, 840)`。

**口播：**

Anthropic 把界限划得很清楚：

Workflow 是提前把路径写好，模型和工具照着走；

Agent 不一样，下一步做什么、工具怎么用，由模型在运行时判断。

区别就在这儿——谁来决定下一步。

**画面与调度：**

0–3 秒，保留原图的来源识别，聚焦正文“workflows and agents”所在位置，浏览器导航与推荐文章退出主要构图。

说到 Workflow，在对应原句旁强调短引：

> orchestrated through predefined code paths

右侧以中文意译：“按预定义代码路径组织”。一条预先连好的中性灰路径随句子展开，不插入具体任务。

说到 Agent，视线下移到原图红框，强调短引：

> LLMs dynamically direct their own processes and tool usage

右侧意译替换为：“模型动态决定执行过程与工具使用”。模型位置变蓝，下一段路径在决策之后才接出。

最后约 3 秒保持两行中文对照。区别放在谁主导执行过程，不把 Workflow 描述成不能分支、不能循环。

**素材与来源：** [image.png](./assets/image.png)；[Anthropic：Building effective agents](https://www.anthropic.com/research/building-effective-agents) 的“What are agents?”。上面两段是原文节选；中文是意译。

模型负责判断，工具负责和外部系统打交道，指令规定目标、行为和边界。

### S05 · 把两家的重点合成一句话

1:01–1:19 / 18 秒 / 帧 `[1830, 2370)`。

**口播：**

把两家放在一起看：

Agent 是让大模型在执行中做决策，借助工具和反馈，推进用户任务的系统。

关键在这儿——模型不只是给出答案，它还参与决定接下来怎么做。

**画面与调度：**

上镜的系统框保持不动。左上角回收 Anthropic 的中文要点“动态决定过程与工具使用”，右上角回收 OpenAI 的中文要点“代表用户完成任务”。每条各带自己的来源名。

说到“放在一起”，两条要点向中央引出细线，中央出现“本片归纳”，再展开完整句子：

> Agent：让大模型在执行中做决策，借助工具和反馈，推进用户任务的系统。

按口播顺序强调“执行中做决策”“工具和反馈”“用户任务”。整句出现后保持位置，不拆成快速闪过的标语。

最后一句时只强调“模型参与决定下一步”，其余结构仍然可见。末尾留约 1 秒静止，再沿“反馈”的连接线进入 S06。

**素材与来源：** 综合两家原文形成的讲述用定义，不是任一家公司的逐字原句。反馈机制另见 Anthropic 的“Agents”部分；与 S02 的架构区别、S03 的任务定义共同使用。

### S06 · 用一张简图，看懂决策和反馈

1:19–1:34 / 15 秒 / 帧 `[2370, 2820)`。

**口播：**

实际运行起来，是一轮一轮往前走的：

模型提出下一步，程序真正去执行工具，结果再交回模型。

模型看到结果，再决定是继续、调整，还是结束。

**画面与调度：**

0–2 秒，短暂带出附件循环图的主体，与刚才的“反馈”连接线对应。随后接成同一套配色的简图，画面只保留三个主要位置：

```text
模型决定下一步 → 程序执行工具 → 返回执行结果
       ↑                         │
       └──────── 反馈 ───────────┘
```

用户目标放在左上方，作为持续输入，不单开新的例子。

“程序执行工具”说出口之后，执行位置才从待命变为运行；结果返回后，模型旁的下一步才更新。最后从模型位置分出“继续／调整”和“完成”两类出口，保留约 2 秒。

用这一轮动作说明系统根据结果继续推进。模型提出动作与程序执行工具明确分开；不展开 Harness、JSON、参数检查或具体任务演示。

**素材与来源：** [image 1.png](./assets/image%201.png) 是原稿的解释图，不作为大公司原文引用；简图依据 [Anthropic 文章的“Agents”部分](https://www.anthropic.com/research/building-effective-agents) 所述环境反馈与循环机制。图是简化的常见工具交互过程，不要求每项任务都经过固定轮数。

### S07 · 能自主推进，也要有停止和交还控制的出口

1:34–1:48 / 14 秒 / 帧 `[2820, 3240)`。

**口播：**

当然，自主不等于没有边界。

它得在既定约束里运行：任务完成就停；

处理不了，或者需要你来做决定，就把控制权交还给你。

**画面与调度：**

延续上镜同一张图，黄色约束边线围住执行范围，不新增复杂架构。

“完成”出口落到用户可拿到的结果；“处理不了”与“需要人来决定”合到“暂停／交还控制”出口。经过对应口播，循环才停止，不能一边标“等待人”一边继续执行。

右侧来源签依次标出“OpenAI · What is an agent?”和“Anthropic · Agents”。最后约 2 秒同时保留“目标”“模型决策”“工具反馈”和“退出条件”，准备收成尾帧。

**素材与来源：** [OpenAI 指南](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/) 关于约束、完成判断、失败时交还控制的说明；[Anthropic 文章](https://www.anthropic.com/research/building-effective-agents) 关于人工反馈与停止条件的说明。
