# 制作与校验

按本次任务读取相关部分。以下是从现有三个工程提炼的经验；代码路径均相对仓库根目录。实施前检查目标项目的 `package.json`、合成入口、字体与素材状态，再使用它已有的脚本和组件。

## 1. 明确正文和时间的来源

初始分镜负责保留创作方案，当前剪辑负责实际播放。两个较新的工程使用 `public/narration/manifest.json` 保存编辑后的正文、字幕时间和录音；它可能是未提交的本地文件，不能假设一定存在。没有保存剪辑时使用项目定义的初始数据。

- `workflow-vs-agent`：初稿在 `src/data/storyboard.json`；`src/voiceover.metadata.ts` 加载保存状态，`src/Film.tsx` 根据解析后的项目排镜头，章节合成也要用相同剪辑。
- `agent-product-landscape-2026`：`src/data/shots.json` 是基础镜头，`src/voiceover.config.ts` 的 `resolveVoiceTimeline` 将保存字幕与镜头关联；`production/SHOT_CRAFT.md` 明确当前正文和时间以 manifest 为准。
- `chatgpt-to-agent`：`src/data/story.ts` 的 `SHOTS`、`CAPTIONS` 是静态分镜与字幕；不能直接假设它已有后续工程的全部弹性剪辑能力。

改动前确认数据流：原稿 → 基础分镜 → 当前剪辑 → 预览、音轨、SRT、章节、导出 metadata。脚本生成的数据与人工编辑数据应有清楚边界。若同步脚本缺少原稿，就检查现有数据并说明缺失，不用臆造原稿覆盖当前剪辑。

## 2. 分开处理三种时间

| 时间 | 用途 | 修改时的要点 |
| --- | --- | --- |
| 全片帧 | 镜头起点、字幕绝对位置、音轨、章节与全片音乐 | 修改某段后顺延下游；导出总帧数同步更新 |
| 镜头局部帧 | 当前镜头内的编排与相机状态 | 通常由全片帧减去镜头起点得到；进入子序列后避免再重复扣起点 |
| 动作进度 | 展开、分裂、调用往返等短动作 | 绑定正在讲的语义阶段；到位后保持，需要循环的环境层继续按实际帧运行 |

以整数帧作为最终边界，秒数与帧数转换集中处理，沿用项目的取整约定。留意全片与章节播放的偏移，以及进入 `Sequence` 后的局部坐标。

### 动作怎样跟着口播

`agent-product-landscape-2026/src/lib/timeline.ts` 的 `motionSpansFor`、`motionStateFor` 和 `animationTimeFor` 展示了同一套映射的三个用途：根据字幕选择当前阶段、计算动作画面、把视觉事件映射回实际音效时间。

可复用的方法：

1. 标出每个状态改变属于哪句口播。
2. 给动作本身设置合适的完成时间，剩余镜头时间用于保持与阅读。
3. 改句长后用新切点驱动相机、状态和提示音；增删或改写句子后重新确认锚点。
4. 将持续的漂浮、环绕等环境运动与短动作进度分开，避免整层被固定在最后一帧。

样本中的 `src/lib/cue-match.ts` 用正文匹配保留阶段关联。沿用这种实现时要抽查匹配结果，尤其是新增句、合并句与相似文本；仅沿用数组序号容易指错动作。

`workflow-vs-agent/src/Film.tsx` 也有整镜按新时长映射的实现。小幅调整或普通镜头可沿用；对速度和语义敏感的爆裂、分裂、撞击等动作，应检查是否被拖慢或抢演，再决定是否需要按阶段处理。

## 3. 录音不被初稿时长截断

若任务涉及配音编辑，保持这些可观察行为：

- 一句话自然读完，再推进下一句；实际读得更久时，保存完整音频并调整相关字幕、镜头和后续内容。
- 人声保持正常语速。弹性镜头可延长；固定包装镜头容不下旁白时，明确调整稿件或镜头配置。
- 试听与正式保存有区别，放弃试听能恢复保存状态；重录保留可恢复的原音频。
- 逐镜人声与整片人声有明确覆盖顺序，避免重复发声；短录音留下的空白不应意外漏出被替换的旧人声。
- 延长前面一句时，已有的后续录音也要正确移动；刷新、章节播放和视频导出应恢复同一剪辑。

参考 `workflow-vs-agent/README.md` 的真人配音说明，以及 `agent-product-landscape-2026/src/voiceover.config.ts` 的 `resolveFilmVoiceTracks`。普通视频任务复用现有录音入口即可，不因此重做一套录音产品。

## 4. 转场、字幕和连续画面

- `chatgpt-to-agent/src/Film.tsx` 给转场增加前后把手，`src/data/story.ts` 明确字幕保持绝对分镜时钟。改变重叠长度时，复查总帧数和真正切点。
- `agent-product-landscape-2026/production/SHOT_CRAFT.md` 要求叠化期间上一镜保持末态，字幕在转场与撞击之上显示，末句结束后再退出。
- 需要比较的结构可以放进连续的空间中；`workflow-vs-agent` 的五种模式共用一个蓝图段落，配音调整后这段内部定位也必须跟随。
- 片头、章节卡和片尾可以有自己的节奏，不能只靠给每镜套相同转场完成剪辑。

实现动画时根据帧号计算状态，使用固定种子的随机效果。GIF 可以预拆帧后按时间索引，或使用项目中能确定性寻帧的现有方案；用任意帧跳转和重复渲染检查一致性。

## 5. 人声、音乐与提示音

先试听原始人声，再决定音乐电平。人声段需要清楚，提示音与关键事件对应，片头片尾平滑进出。长片配乐需要覆盖整片，续接处避免突变，章节切换通常维持音乐连续。

项目中的数值只说明当时如何混音：

| 工程 | 已有配置 | 使用边界 |
| --- | --- | --- |
| `chatgpt-to-agent/src/Film.tsx` | 音乐正常 0.08、人声时 0.03，带淡入淡出 | 仅是该素材的增益系数 |
| `workflow-vs-agent/src/components/Soundtrack.tsx` | 正常 0.12、人声时 0.045；4 秒交叉续接；提示音 0.15 | 原曲与录音换了，需重新试听 |
| `agent-product-landscape-2026/src/lib/music.ts` | 基础 0.2，按全片时长淡入淡出 | 当前实现未在此函数按人声压低，不能声称三个工程都有同一种混音逻辑 |

这些增益系数不等于统一响度标准。复用音乐、字体、截图和音效时保留各自来源与授权说明；替换素材后同步署名。

## 6. 素材与事实对应

为关键截图保留素材 ID、来源、时间语境、原图与裁切关系。需要追踪素材变动时沿用清单和校验值；截图切产品时，来源标签一起切换。

近期界面用于展示当前外观，历史发布或历史能力需要对应年代的依据。自绘图解、演示数字、任务状态和模拟运行画面标作示意，不能充当产品性能实测。字体和图片从本地稳定加载，检查中文缺字、截图拉伸、裁切与过度放大。

参考 `agent-product-landscape-2026/production/assets.json`、`production/source-provenance.json`、`production/SOURCES.md` 与 `src/components/Media.tsx`。

## 7. 校验与交付

只改稿件时检查朗读、解释、来源和时长，不必运行整套视频测试。改实现时选择与变更相关的已有脚本；预览网页构建成功不代表已经导出视频。

| 变更 | 重点验证 |
| --- | --- |
| 口播、分镜、时长 | 字幕可读且不越镜；镜头连续；章节与总时长一致 |
| 配音或剪辑功能 | 延长、缩短、新增、删除句子后，后续字幕、镜头、音轨、metadata、SRT 联动；刷新可恢复 |
| 关键动作或转场 | 动作前、中、后与接缝抽帧；字幕不被遮；无抢演、意外定格或拖慢 |
| 音轨与混音 | 人声完整；局部覆盖正确；音乐续接与提示音对齐；章节偏移正确 |
| 预览或合成入口 | 同一 Film 与同一剪辑数据驱动预览和导出；真实分辨率与缩放窗口可读 |

时间轴功能的回归可以参考 `workflow-vs-agent/scripts/test-timing.ts`、`scripts/test-edit-timing.ts` 和 `agent-product-landscape-2026/scripts/test-edit-timing.ts`。录音测试使用模拟麦克风和独立临时数据，保留正式录音。

最终视频交付需要实际导出与检查；只完成 skill、稿件或分镜时，按该交付范围说明验证，不额外渲染整片。

## 估时参数备忘

`agent-product-landscape-2026/production/SHOT_CRAFT.md` 使用过约每秒 3.8 个汉字估时，另计英文、数字、标点和停顿；镜头头留约 0.5 秒、句间约 0.17 秒、尾约 0.8 秒，动作提前约 0.2 秒进入，常在 0.6–3.7 秒完成，交接用 12 帧叠化。

这些是该片初排参数。它们可帮助起稿，之后仍以实际朗读、读图负担和试听为准，不作为新片必须满足的节奏标准。
