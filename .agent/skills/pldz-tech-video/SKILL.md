# PLDZ 技术视频创作

拿到新材料后，主动做出选材、讲法和画面的选择，完成用户要的稿件或视频。成稿应让观众跟得上正在发生的事，也能听出主讲人自己的判断。

## 按请求直接推进

- **新创作：** 从主题或材料选角度，组织讲述，设计视觉事件，交付完整口播或分镜。已有足够材料时继续成稿，不停在分析风格或提出计划。
- **改稿：** 保留有效内容与作者原话，找到最影响理解的地方，连同必要上下文一起改。用户选定的角度、结构和素材优先。
- **Review：** 指到具体句子或镜头，说明观众会在哪里听不懂、看不清或觉得做作，给可直接替换的版本。不要用一轮风格总结代替修改建议。
- 从请求推断受众、片长、发布形式与交付物。非关键缺项用简短假设推进；事实缺失先补资料。只要口播就交口播，只要分镜就完成分镜；实现视频时沿用目标项目现有引擎。

## 随身保留的创作偏好

新主题可以直接使用这些默认值，无须先重读旧项目：

- **语气：** 像带大家看材料、看例子，再说自己的判断。多说具体动词、实际结果和人的参与；长短句自然变化。第一人称交代选材和判断，个人实测与经历需要依据。
- **视觉：** Google 四色作强调，白／近白打底，淡色面铺层次，深灰文字保持可读。蓝 `#4285F4`、红 `#EA4335`、黄 `#FBBC04`、绿 `#34A853`；浅色可用 `#E8F0FE`、`#FCE8E6`、`#FEF7E0`、`#E6F4EA`。按内容选择颜色角色，不必四色同时出现。
- **动作：** 把技术关系变成画面中的事件，允许鲜明的运镜、形变、快慢与动静变化；读字与看结构时给稳定窗口。
- **收束：** 完成本期提出的事。选型内容可留下判断依据，机制讲清也可以直接道谢。关注卡与系列包装按本次需要采用。

语气参考：“AI 选好工具，程序去跑。结果回来，再决定下一步。”“任务一多，得看看谁卡住了，谁还在等你确认。”学习它们的具体与顺口，为新题材重新写句子。

## 从主题选出值得讲的一件事

先形成一个足够具体的创作判断：**观众正遇到什么，看完能弄懂或判断什么，靠哪个可展示的现象讲清。** 这可以只是一句工作笔记，不必额外输出策划报告。

- 材料很宽时，试出不同入口：从一次失败跟下去、让两种做法面对同一个任务、追踪一次请求或交付、解释一次能力变化。按受众疑问、证据充分度、片长与画面可表达性选择。
- 用户已选角度时直接深化。若用户要创意方案，给有不同开场、推进逻辑和画面事件的备选；只要成稿时，自己选定最合适的讲法并继续写。
- 选择能在镜头里看见差别的例子：前后状态、两种结果、一次异常或一个需要判断的时刻。删去不能帮助本期理解的旁支，不照着原材料每个小标题平均分镜。
- 创意可以改变视角、顺序、例子、比喻和构图；事实、因果关系与用户明确的结论仍须有依据。产品现状、年份、数据和能力需要相应资料，示例设定与模拟结果要标明。

## 把材料组织成一段讲述

按本期真正的理解难点组织，不预设统一的六段式：

- **解释机制：** 选一次具体执行，跟着输入、变化和结果走，在观众需要时补概念。
- **比较方案：** 给相同任务或条件，看哪里开始分岔、结果有什么不同，再讲适用条件。
- **回顾发展：** 以使用方式和能力缺口串节点，产品与时间提供证据；允许路线并存。
- **教程或实践：** 朝一个可检查的产物推进，在实际决策、失败与修正处展开。

让每段带来一点新理解：补前提、做选择、遇到例外、看到结果，或回收前面的疑问。段落之间可以自然补充、对比、举例或转场；无需每段设问，也无需每镜结束后加总结。

章节和镜头数量服从这条讲述。概念比较可以贯穿同一任务，较宽的回顾可以使用不同短场景。先把关键口播与视觉事件搭在一起，发现画面难以说明时，回头改讲法和例子。

## 为这个题材发明一套画面

先找需要表现的关系，再决定对象长什么样：

1. 列出关键实体、关系，以及这次到底什么改变、什么保持不变。对象、位置、颜色和状态要让观众能持续认出它们。
2. 难点可以试两种表现：直接展示真实界面或数据，或者设计能保持因果关系的空间隐喻。选择能演示本期变化、能延续到后续镜头、不会引入错误理解的方案。
3. 给关系安排动作：先后可以沿空间展开，竞争可以争同一位置，积压可以形成等待，隐藏状态可以被揭开。它们只是出发点，具体对象与运动从本次材料中生长。
4. 确定一个可延续的视觉规则，例如同一对象变形、同一空间换尺度、相同输入走两种路径。后续镜头沿这条规则扩展；新视觉承担新信息。
5. 用一次揭示、对照或状态变化表现最关键的理解转折。强镜头可留在这里，其他镜头负责铺垫、解释和消化结果。

旧作品的光球、轨道、笔与任务卡是可选手法，不是新题材的默认演员。若隐喻只能说明一半关系，改用实际图解，或在需要处明确回到技术机制。按用户预算、素材和现有实现条件取舍。

## 给每一镜编排事件与视线

先确定“这一镜观众会看懂什么”，再写发生的事，最后选拍法。按需要写清：

> 初态与关注点 → 哪句口播触发变化 → 对象怎样行动或变形 → 相机／焦点怎样跟上 → 最终状态与下镜交接。

- 跟拍让人追踪一个过程，拉远揭开整体，焦点转移交接注意力，分屏便于同时比较，急停强调阻塞。选择手法时，说得出它帮助观众理解什么即可，不必每镜写满术语和参数。
- 镜头之间延续一个对象、方向、动作或问题。截图可以转为图解，局部可以拉回全景，结果可以成为下一镜输入，避免每镜从空白重新堆卡片。
- 动作跟着正在讲的语义推进，关键变化不提前抢演。动作本身的力度与镜头的阅读时长分开安排，持续环境运动可以继续。
- 先给正文留下实际时间预算。没有录音时，可按每秒约 3.8–4 个汉字粗估，另计英文、数字与停顿；这是起稿参考，之后用朗读校准。读图若与旁白同时发生不重复计时，旁白之后另留的停顿则计入镜头。逐镜估时加起来应接近目标片长；超时先合并重复论述或缩小范围，不硬挤语速。

写完整 `Storyboard.md`、需要具体格式或遇到创作瓶颈时，读 [从材料到分镜](references/storyboard-writing.md)。该参考包含选择方法和全新题材的完成示例。

## 把口播写到能直接录

- 用“谁做了什么、结果怎样、接着怎么办”展开。第一次解释陌生机制时可先说它做什么；熟悉或讲过的术语直接使用。
- 用“我会先看”“这里”“你看”时给出对应材料或判断，不把它们当口语装饰。限制与代价就着相关内容说明，不给每个功能附加一段告诫。
- 读一遍：空泛的名词句换成实际动作，重复上一句的抽象尾句删去，刻意的反转、排比和口癖按语义取舍。保留有内容的长句与自然停顿。
- 标题写这一镜的动作、处境或问题；口播按意群分段。制作指令与提词分开，无旁白镜头明确标注。

## 交付与最后一遍修改

- **口播：** 提供完整可读的稿件，判断有没有解释跳跃、无内容的漂亮句子和未经依据的经历。
- **分镜：** 提供能制作的 `Storyboard.md`，包含逐镜口播、画面事件、必要调度与时间估计。串读正文、连看镜头，改掉重复用途和突然失去的对象或线索。
- **视频实现：** 把当前稿件与时间落实到合成，实际检查画面、配音、字幕、转场和导出。涉及实现、剪辑或声音时读 [制作与校验](references/production.md)，复用当前权威剪辑数据。
- Review 要把发现落到可改的片段；成稿要体现选择的结果，默认不附整段推演和旧作分析。说明实际完成和验证到哪一步。

只有需要核对用户原句、已有品牌细节或偏好来源时，再读 [历史风格依据](references/style-evidence.md)。归纳旧作不是新创作的前置交付。
